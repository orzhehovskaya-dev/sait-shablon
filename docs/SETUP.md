# Запуск сайту: покрокова інструкція

Порядок важливий: кожен крок дає ключі, які потрібні на наступних. Усі ключі — це змінні середовища з файлу `.env.example`. Орієнтовний час — 2–3 години, більшість — очікування підтверджень (домен, пошта).

Що знадобиться: GitHub-акаунт, домен, iPhone з Apple ID, ФОП з активним WayForPay.

**Як зрозуміти, що крок спрацював.** В адмінці є сторінка **Підключення** (`/admin/status`). Після кожного кроку натискай там «Перевірити» — сайт робить справжній запит до сервісу. Поки перевірка не пройшла, сервіс позначений «Не перевірено» або «Помилка», а не «Працює». Оплата, календар, Zoom, лист і Telegram позначаються як робочі лише після справжнього тестового бронювання (крок 11).

## Як безпечно зберігати секретні ключі

Секретні ключі (Merchant Secret Key, паролі, токени) живуть лише в **змінних середовища сервера** на Vercel. Звідти їх читає тільки серверний код; у браузер, код на GitHub і в чат вони не потрапляють.

1. Vercel → твій проєкт → **Settings → Environment Variables**.
2. **Key** — назва змінної (наприклад, `WAYFORPAY_SECRET_KEY`), **Value** — встав ключ, скопійований безпосередньо з кабінету сервісу.
3. Увімкни перемикач **Sensitive** — після збереження значення більше не можна переглянути навіть у Vercel, лише замінити.
4. Environments: **Production** (і Preview, якщо тестуватимеш там).
5. **Save** → **Deployments → … → Redeploy**, щоб сайт підхопив нове значення.

Правила:
- Ніколи не вставляй секрети в код, у файли репозиторію, у чати (зокрема зі мною), у скриншоти.
- Секретні змінні ніколи не починаються з `NEXT_PUBLIC_` — такий префікс робить змінну видимою в браузері.
- Файл `.env.local` (для локального запуску) вже в `.gitignore` — він не потрапить на GitHub.
- Якщо ключ десь засвітився — згенеруй новий у кабінеті сервісу (для WayForPay — через особистий кабінет або підтримку) і заміни змінну.

## 1. Код на GitHub

1. Відкрий шаблон на GitHub і натисни **Use this template → Create a new repository**.
2. Назва - будь-яка (наприклад, `my-site`), доступ - **Private**.

Локально (за бажанням, потрібен Node.js 20+):

```bash
npm install
cp .env.example .env.local   # заповнюй поступово
npm run dev                  # http://localhost:3000
npm test                     # автотести логіки слотів, оплат, календаря
```

## 2. Публікація на Vercel і твій домен

1. vercel.com → **Add New → Project** → обери репозиторій з GitHub → Framework: Next.js (визначиться сам).
2. **Environment Variables**: поки що додай лише `NEXT_PUBLIC_SITE_URL` = `https://твій-домен` (без `/` у кінці). Решту змінних додаватимеш на наступних кроках — сайт уже відкриється, а бронювання чесно показуватиме «ще не підключено».
3. **Deploy**.
4. **Project → Settings → Domains → Add** → твій домен. Vercel покаже DNS-записи (зазвичай `A` для кореня і `CNAME` для `www`) — додай їх у панелі реєстратора домену. HTTPS увімкнеться автоматично.
5. Після кожної зміни змінних середовища — **Deployments → Redeploy**.

Тариф: потрібен **Pro** (Settings → Billing). На безкоштовному Hobby заборонені сайти, які заробляють, і планувальник (`vercel.json`, кожні 10 хвилин) не дозволений - публікація завершиться помилкою.

## 3. Supabase — база даних і вхід в адмінку

1. supabase.com → **New project**. Регіон — `Central EU (Frankfurt)`. Збережи пароль бази.
2. **SQL Editor → New query** → встав увесь вміст `supabase/migrations/0001_init.sql` → **Run**. Має бути «Success». Потім так само `0002_integration_checks.sql`. Файл `0003_…` на новій базі не потрібен (лише якщо `0001` виконували до 18.10.2026).
3. **Project Settings → API**: скопіюй
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` → `SUPABASE_SERVICE_ROLE_KEY` (секрет — нікому не надсилай)
4. **Authentication → Providers → Email**: вимкни «Allow new users to sign up» — щоб ніхто сторонній не міг зареєструватися.
5. **Authentication → Users → Add user → Create new user**: твій email і надійний пароль, «Auto confirm user» — увімкнено.
6. Зроби себе власницею: **SQL Editor**:
   ```sql
   insert into admin_users (user_id, role)
   select id, 'owner' from auth.users where email = 'ТВІЙ_EMAIL';
   ```
   Для асистентки (лише перегляд) — так само, з `'assistant'`.

## 4. WayForPay

1. В особистому кабінеті WayForPay: **Налаштування магазину** → додай домен сайту. WayForPay перевіряє сайт перед активацією, тому до подачі **заповни реквізити ФОП** у `content/site.ts → legal` і перевір сторінки `/oferta` та `/privacy` — там мають бути оферта, контакти, умови повернення.
2. Скопіюй **Merchant login** → `WAYFORPAY_MERCHANT_ACCOUNT`, **Merchant secret key** → `WAYFORPAY_SECRET_KEY` (з позначкою Sensitive — див. «Як безпечно зберігати секретні ключі» вгорі). Копіюй прямо з кабінету у Vercel, без проміжних нотаток і месенджерів.
3. Адмінка → **Підключення → WayForPay → Перевірити**. Сайт надсилає запит статусу неіснуючого замовлення (гроші не списуються). Відповідь «Order Not Found» означає, що ключі прийнято; «Invalid signature» — невірний секретний ключ; «Account Not Found» — невірний логін.
4. `WAYFORPAY_MERCHANT_DOMAIN` — домен без `https://`, точно як зареєстрований у WayForPay.
5. **Валюта — перевір до запуску** (напиши в підтримку WayForPay або менеджеру):
   - чи можна для твого ФОП приймати платежі **в EUR**;
   - у якій валюті буде **розрахунок** на рахунок ФОП (зазвичай гривня) і за яким курсом;
   - чи увімкнені Apple Pay / Google Pay.

   Варіанти налаштування:
   - EUR дозволено → `WAYFORPAY_CURRENCY=EUR` (на сайті й у платежі — євро).
   - Лише гривня → `WAYFORPAY_CURRENCY=UAH` і `WAYFORPAY_EUR_RATE=auto`. На сайті ціни в євро, клієнт платить еквівалент у гривні за офіційним курсом НБУ на день оплати (сайт оновлює курс автоматично). Можна й зафіксувати свій курс числом, наприклад `52`.
6. URL для сповіщень (serviceUrl) налаштовувати в кабінеті не потрібно — сайт передає його в кожному платежі: `https://твій-домен/api/wayforpay/callback`.

Що вже реалізовано:
- 100% передоплата; ціни бере сервер з `content/services.ts` — підмінити суму в браузері неможливо.
- Підпис платежу формується на сервері; секретний ключ у браузер не потрапляє.
- Бронювання підтверджується **лише** після перевіреного підпису сповіщення від WayForPay або серверного запиту статусу (`CHECK_STATUS`). Перевіряється і сума, і валюта.
- Повторні сповіщення про один платіж не створюють другої зустрічі чи другого листа.
- Слот тримається 20 хв (`BOOKING_HOLD_MINUTES`), платіжна сторінка WayForPay діє стільки ж; після цього слот автоматично звільняється.
- Якщо оплата прийшла після звільнення, а час уже зайнято — статус «Конфлікт часу», тобі приходить сповіщення в Telegram, клієнт бачить пояснення. Рішення — інший час або повернення з адмінки.
- Повернення (повне або часткове) і скасування — кнопками в адмінці; подія в календарі та Zoom видаляються автоматично.

## 5. Apple Calendar (iCloud) — щоб сайт бачив твою зайнятість

Сайт підключається до iCloud напряму через CalDAV — офіційний протокол Apple. Ти й далі користуєшся звичайним «Календарем» на iPhone.

1. На iPhone: **Календар → Календарі → Додати календар** → назва **`Мої зустрічі`**, обліковий запис **iCloud**. Сюди сайт записуватиме оплачені зустрічі (з посиланням на анкету й Zoom).
2. appleid.apple.com → **Вхід і безпека → Паролі застосунків → +** → назва «Мій сайт» → скопіюй пароль вигляду `abcd-efgh-ijkl-mnop`.
   - Потрібна увімкнена двофакторна автентифікація (на iPhone вона зазвичай уже є).
3. Змінні:
   - `ICLOUD_APPLE_ID` — твій Apple ID (email)
   - `ICLOUD_APP_PASSWORD` — пароль застосунку з кроку 2 (НЕ основний пароль)
   - `ICLOUD_BOOKING_CALENDAR` — `Мої зустрічі` (точно як назва календаря)
   - `ICLOUD_IGNORE_CALENDARS` — календарі, які не мають блокувати час, через кому (наприклад `Свята,Дні народження`)
   - `ICLOUD_ALLDAY_BLOCKS` — `true`: подія «на весь день» (відпустка, зйомка) закриває весь день.

Як це працює:
- Будь-яка подія в будь-якому твоєму календарі iCloud = зайнятий час (плюс 30 хв перерви до і після).
- Подія з позначкою «Показувати як: Вільно» не блокує час.
- Повторювані події (щотижневі тренування тощо) враховуються.
- Якщо iCloud тимчасово недоступний, сайт **не показує слотів узагалі** — краще ніж показати зайнятий час.
- Якщо ти колись зміниш пароль Apple ID, пароль застосунку перестане діяти — створи новий і онови змінну.

> Чому не Calendly / Cal.com: вони вміють читати iCloud, але приймають оплату лише через Stripe/PayPal і не можуть «тримати» слот під час оплати WayForPay. Власний движок на сайті вирішує це надійніше.

## 6. Zoom — автоматичні посилання

1. marketplace.zoom.us → **Develop → Build App → Server-to-Server OAuth** → назва «My Booking».
2. Скопіюй `Account ID`, `Client ID`, `Client Secret` → `ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET`.
3. **Scopes**: додай `meeting:write:meeting:admin` і `meeting:delete:meeting:admin` (або `meeting:write:admin` у старому інтерфейсі).
4. **Activation → Activate**.

Потрібен платний Zoom (Pro), інакше зустрічі обмежені 40 хвилинами.

Запасний варіант без API: `ZOOM_FALLBACK_LINK` = посилання на твою персональну кімнату. Тоді всі клієнти отримають одне постійне посилання.

## 7. Telegram-сповіщення

1. У Telegram напиши **@BotFather** → `/newbot` → назва «Мій сайт - оплати» → отримаєш токен → `TELEGRAM_BOT_TOKEN`.
2. Відкрий свого нового бота і натисни **Start** (інакше бот не зможе тобі писати).
3. Дізнайся свій id: напиши **@userinfobot** → він відповість числом → `TELEGRAM_CHAT_ID`.

Бот надсилає повідомлення лише в особистий чат (сайт перевіряє, що id — особистий, а не група чи канал). У повідомленні — коротка інформація і кнопка «Відкрити анкету», яка веде в адмінку й відкривається лише після входу.

## 8. Пошта для клієнтів (Resend)

1. resend.com → реєстрація → **Domains → Add domain** → твій домен.
2. Додай DNS-записи, які покаже Resend, у панелі свого домену. Дочекайся статусу **Verified** (від кількох хвилин до кількох годин).
3. **API Keys → Create** → `RESEND_API_KEY`.
4. `EMAIL_FROM` = `Твоє Ім'я <hello@твій-домен>`; `EMAIL_REPLY_TO` = пошта, куди клієнти відповідатимуть.

Безкоштовного тарифу Resend (3 000 листів на місяць) вистачить із запасом.

## 9. Планувальник (нагадування, звільнення слотів, перевірка платежів)

Сайт має службову адресу `/api/cron/tick`, яку треба викликати кожні 10 хвилин. Вона:
- звільняє прострочені утримання слотів;
- перевіряє в WayForPay платежі, по яких не прийшло сповіщення;
- надсилає нагадування за 24 години;
- повторює кроки, що не вдалися (Zoom, календар, лист, Telegram).

1. Згенеруй секрет: будь-який довгий випадковий рядок (наприклад, у Терміналі Mac: `openssl rand -hex 32`) → `CRON_SECRET`.
2. Планувальник уже налаштований у `vercel.json` (кожні 10 хвилин) і працює на тарифі Vercel Pro. Додати треба лише `CRON_SECRET` у Environment Variables.
3. Запасний варіант, якщо ти тимчасово на Hobby: зміни розклад у `vercel.json` на `0 6 * * *` (раз на добу) і налаштуй зовнішній виклик кожні 10 хвилин:
   - cron-job.org → реєстрація → **Create cronjob**
   - URL: `https://твій-домен/api/cron/tick`
   - Розклад: кожні 10 хвилин
   - **Advanced → Headers**: `Authorization` = `Bearer ТВІЙ_CRON_SECRET`
   - Збережи і натисни «Test run» → у відповіді має бути JSON з `expired`, `synced`, `reminders`.

## 10. Аналітика (необов'язково)

- **GA4**: analytics.google.com → створи ресурс → Data stream «Web» → `Measurement ID` (`G-XXXX`) → `NEXT_PUBLIC_GA4_ID`.
- **Meta Pixel**: Events Manager → Pixel ID → `NEXT_PUBLIC_META_PIXEL_ID`.

Аналітика вмикається лише після згоди відвідувача в банері cookies. Події воронки: `service_click`, `view_service`, `begin_booking`, `select_slot`, `form_complete`, `begin_checkout`, `purchase` (з назвою послуги і сумою). Ім'я, email, Instagram і відповіді анкети в аналітику не передаються.

У GA4 позначи `purchase` як ключову подію (Admin → Events → Mark as key event). Конверсію кожної послуги бачиш у звіті Events з розбивкою за параметром `service` (зареєструй його в Admin → Custom definitions → Custom dimension, scope Event, parameter `service`). Посилання з Instagram додавай з UTM, наприклад `https://твій-домен/?utm_source=instagram&utm_medium=bio` — джерело збережеться і в бронюванні в адмінці.

## 11. Наскрізний тест (обов'язково перед запуском)

Поки цей тест не пройдено, оплату, календар і сповіщення не можна вважати робочими. Адмінка → **Підключення → Наскрізний тест бронювання** показує, що вже підтверджено реальними подіями.

Пройди сценарії з реальною карткою (потім зроби повернення з адмінки):

- [ ] Сторінка бронювання показує слоти; створи подію в «Календарі» на iPhone — через хвилину цей час зник на сайті.
- [ ] Повна оплата аудиту → сторінка «Оплату отримано» з анкетою, лист із Zoom, файлом календаря та посиланням на анкету, повідомлення в Telegram, подія в календарі «Мої зустрічі».
- [ ] Заповни анкету на сторінці після оплати → прийде друге Telegram-повідомлення «Анкету заповнено», в адмінці з'являться відповіді.
- [ ] Закрити сторінку оплати, не заплативши → через 20 хв слот знову вільний.
- [ ] Відхилений платіж (наприклад, картка без коштів) → сторінка «Оплату не завершено», анкета збережена.
- [ ] Два браузери, один і той самий час → другий отримує «Цей час щойно зайняли».
- [ ] Повернення з адмінки → статус «Повернено», подія і Zoom видалені, клієнт отримав лист.
- [ ] Заблокуй день в адмінці → він зникає з бронювання.
- [ ] CSV експорт відкривається в Excel / Numbers з кирилицею.
- [ ] Перевір сайт на iPhone в Safari та у вбудованому браузері Instagram.

## Що замінити в контенті

Усе в двох файлах:

- `content/site.ts` — тексти головної, фото, кейси, відгуки, FAQ, правила перенесення/скасування, реквізити ФОП, контакти (`telegramContact`, `email`).
- `content/services.ts` — назви, ціни, тривалість, склад послуг, таблиця порівняння, інструкції з підготовки для листа.

Фото: поклади файли в `public/images/` (JPG/WebP, портрет, від 1200 px завширшки) і зміни шляхи в `content/site.ts`. Зараз там стоять заглушки. Також можна замінити `public/og.jpg` (картинка для прев'ю посилання, 1200×630).

Кейси та відгуки: додай об'єкти в `cases.items` і `reviews.items` (приклад структури — у коментарях файлу), скриншоти — у `public/images/cases/`. Поки списки порожні, ці блоки на робочому сайті не показуються.

Ціни в гривнях сайт рахує сам за офіційним курсом НБУ (оновлення кожні 6 годин). `site.ts → uahRate` — лише запасний курс на випадок, якщо сервіс НБУ недоступний.

Правила перенесення/скасування в `site.ts → policies` — **чернетка**, перевір і відредагуй: вони потрапляють у листи й оферту.
